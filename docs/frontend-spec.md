# TripCast 프론트엔드 — 기획/기능명세서/디자인

백엔드 REST API를 소비하는 React 프론트엔드의 구현 기준 문서입니다. Phase 0~5가 모두 구현됐으며, 이후 변경은 아래 명세와 로드맵을 기준으로 합니다.

## 1. 기술 스택

| 영역            | 선택                                                           | 이유                                                  |
| --------------- | -------------------------------------------------------------- | ----------------------------------------------------- |

## 2. 사이트맵

```
/                    홈 — 3D 히어로 + 서비스 소개 + 오늘의 추천 코스 미리보기
/spots               관광지 검색 (목록 + 지도 토글, `?view=map`)
/spots/:id           관광지 상세 + 날씨
/courses             관광코스 목록
/courses/:id         관광코스 상세 + 통합 날씨
/recommendations     오늘 가기 좋은 코스 추천
/climate?region=     지역별 관광기후지수 (최신 + 기간 차트)
/admin/login         관리자 로그인
/admin               관리자 대시보드 (수동 동기화)
```

## 4. 페이지별 기능 명세

### 3.1 홈 (`/`)

**목적**: 3D 인터랙티브 히어로로 "코스를 여행하는 느낌"을 즉각 전달, 핵심 3개 기능 진입점, 오늘의 추천 코스 미리보기

**사용 API**: `GET /api/tour-courses/recommendations?limit=3`

#### 3D 인터랙티브 히어로 섹션

**씬 구성**

1. **지형(Terrain)**: `PlaneGeometry`를 simplex-noise 기반 heightmap으로 변형한 로우폴리 산악 지형. 외부 3D 에셋 없이 코드로만 생성
2. **경로(Route)**: 시작점~목적지 좌표를 `THREE.CatmullRomCurve3`로 곡선화, 지형 위에 살짝 띄워 배치
3. **웨이포인트 핀**: 곡선 위 주요 지점에 3D 마커 배치
4. **카메라**: `curve.getPointAt(t)`(위치) + `getTangentAt(t)`(시선 방향)로 곡선을 따라 서서히 이동하는 트래킹 샷

**애니메이션 시퀀스** (진입 시 자동 재생, 1회)

| 시점                                   | 동작                                                                                                                                                                |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0~2.5s                                 | **Route drawing animation** — 커스텀 셰이더의 `uProgress` uniform을 0→1로 애니메이션해 경로가 시작점부터 실시간으로 그려짐 (포인트 개수를 늘리는 방식보다 부드러움) |
| 진행률이 웨이포인트 위치를 지나는 순간 | **Waypoint pop-in** — 핀이 scale 0 → 1.15 → 1.0으로 오버슈트되며 등장 (오버슈트 이징으로 바운스 튜닝)                                                               |
| 0~4s (드로잉과 동시)                   | 카메라가 곡선을 따라 패닝, 목적지 부근에서 정지                                                                                                                     |
| 4s 이후                                | 유휴 카메라 흔들림만 유지, 텍스트/CTA 오버레이                                                                                                                      |

**성능·접근성**

- 3D는 무거우므로 정적 블러 이미지 우선 표시 → Canvas `lazy`+`Suspense` 지연 로드 → 페이드 전환
- `prefers-reduced-motion` 켜져 있으면 애니메이션 생략, 완성된 최종 상태 즉시 렌더링
- 모바일/저사양: 지형 폴리곤 축소 또는 정적 일러스트 폴백
- Canvas는 `aria-hidden="true"` (장식용), 실제 정보는 텍스트 오버레이로 별도 제공

**레이아웃**

```
┌─────────────────────────────────────┐
│  [3D 씬: 산악지형 + 경로 애니메이션]    │  ← 전체 화면 배경
│         TripCast                     │  ← 텍스트 오버레이
│   관광지 날씨로 완성하는 나의 여행길      │
│      [오늘의 추천 코스 보기]           │
└─────────────────────────────────────┘
```

#### 히어로 하단 섹션

- 퀵 링크 3개 카드: 관광지 검색(`/spots`) · 관광코스 둘러보기(`/courses`) · 관광기후지수 조회(`/climate`)
- "오늘의 추천 코스" 미리보기: 상위 3개 카드(추천 페이지와 동일 카드 재사용). 로딩 중 스켈레톤 3개, 데이터 없으면 섹션 자체 숨김
- 미리보기 카드 썸네일은 추천 페이지와 같은 `CourseRoadviewThumbnail`(로드뷰)을 씁니다.

### 3.2 관광지 검색 (`/spots`)

**목적**: 이름으로 관광지를 찾고 상세로 진입

**사용 API**: `GET /api/tour-spots?keyword=&page=&size=` → `Page<TourSpotResponse{id,name,latitude,longitude}>`

**화면 구성**

- 검색창(엔터/버튼으로 검색 실행, 타이핑마다 요청 안 보냄) + 검색 버튼
- 보기 전환 토글(목록/지도): `view=map` search param으로 유지하며 검색어·페이지와 함께 URL에 반영
- 목록 보기: 결과 카드 리스트(이름 + 좌표) — 클릭 시 `/spots/:id`. 카드 썸네일은 관광지 좌표 중심의 카카오맵 ROADMAP 정적 화면(`StaticMap`, 레벨 4, 중심 마커)이며 장식 영역(`aria-hidden`)으로 처리합니다. 좌표가 유효하지 않거나 앱 키가 없거나 SDK 로드에 실패하면 공통 대체 화면(`tc-route-visual` + 핀 아이콘)을 보여 주고, 카드 이동은 그대로 가능합니다.
- 지도 보기: 현재 페이지 결과를 카카오맵 마커로 표시, 마커 클릭 시 `/spots/:id`로 이동. 좌표가 유효하지 않은 항목은 마커에서 제외하고 제외된 개수를 안내
- 페이지네이션(이전/다음 + 첫·마지막 페이지 + 현재 페이지 주변 번호, 나머지는 "…" 생략) — 두 보기 공통

**상태**: 검색어 없이 처음 진입 시 전체 목록 노출, 결과 0건이면 "검색 결과가 없습니다"

**디자인**: 카드 썸네일은 16:10 정적 지도(대체 화면에는 지도 핀 아이콘), 좌표는 보조 텍스트로 작게

### 3.3 관광지 상세 (`/spots/:id`)

**목적**: 특정 관광지의 실시간 날씨 + 소속 지역 관광기후지수 확인

**사용 API**: `GET /api/tour-spots/{id}/weather` → `TourSpotWeatherResponse{tourSpotName, latitude, longitude, weather, climateIndex}`, `GET /api/tour-spots/{id}/courses` → `TourSpotCourseResponse[]{courseId, sourceCourseId, representativeSpotName, representativeThemeName, stopCount, startLatitude, startLongitude, endLatitude, endLongitude, spotCourseOrder}`

**화면 구성**

- 제목(관광지명) + 좌표
- 관광기후지수 배지(등급+점수, 없으면 "지수 없음" 중립 배지)
- 날씨 카드(기온, 하늘상태 아이콘, 강수확률, 예보 기준 일시) — `weather`가 null이면 "날씨 정보를 불러오지 못했습니다"
- "이 관광지가 포함된 코스" 목록(`SpotCoursesSection`): 코스별로 테마·대표 관광지·정류지 수·이 관광지의 방문 순서(`spotCourseOrder`)를 보여 주고, 누르면 `/courses/:id`로 이동합니다. 부가 정보라 로딩 중에는 스켈레톤, 실패하면 섹션 안에서만 안내와 "다시 시도" 버튼을 보여 주며 페이지 나머지는 그대로 표시합니다. 포함된 코스가 없으면(`[]`) 섹션을 숨깁니다.
- 지도: 카카오맵에 관광지 위치 마커 1개 표시. `VITE_KAKAO_MAP_APP_KEY`가 없으면 기존 플레이스홀더, SDK 로드에 실패하면 안내 문구 + "다시 시도" 버튼

#### 카카오맵 공통 규칙

- 로드뷰·지도 썸네일은 카드가 화면 근처(200px)에 보일 때만 불러오고, 인스턴스는 동시에 최대 4개까지만 만듭니다(`src/shared/lib/load-limiter.ts`). 파노라마가 뜨거나 타일이 뜬 뒤에야 썸네일을 보여 주며, 그전에는 공통 대체 배경을 유지합니다. 제한 시간(로드뷰 8초, 지도 6초) 안에 뜨지 않아도 다음 카드가 시작됩니다.
- SDK는 `https://dapi.kakao.com/v2/maps/sdk.js?appkey=...&autoload=false`를 한 번만 동적으로 불러옵니다(`src/shared/lib/kakao-maps.ts`). 10초 안에 응답이 없거나 로드에 실패하면 에러로 처리하고 다음 시도에서 다시 불러옵니다.
- 앱 키는 카카오 개발자 콘솔에서 발급하며 코드·커밋에 넣지 않습니다. 콘솔의 **플랫폼 > Web**에 사이트 도메인(로컬 `http://localhost:5173`, 운영 도메인)을 등록해야 지도가 표시됩니다.
- 위경도가 유한하지 않거나 범위를 벗어난 항목(`(0, 0)` 포함)은 지도에서 제외합니다. 표시할 좌표가 하나도 없으면 "위치 정보 없음"을 보여 줍니다.
- 유닛 테스트는 SDK 로더를 mock하고, E2E는 키가 없는 플레이스홀더 상태를 기준으로 검증합니다.

### 3.4 관광코스 목록 (`/courses`)

**목적**: 코스를 페이지 단위로 둘러보기

**사용 API**: `GET /api/tour-courses?page=&size=` → `Page<TourCourseSummaryResponse{courseId, representativeSpotName, representativeThemeName, stopCount}>`

**화면 구성**

- 카드 리스트: "OO 코스"(대표 관광지명), 정류지 N곳, 테마 배지
- 카드 썸네일(`CourseRouteThumbnail`): 드래그·확대를 막은 카카오맵에 출발·도착 지점만 "출발"/"도착" 마커로 표시합니다(같은 위치면 "출발·도착" 하나). 장식 영역(`aria-hidden`)이며 카드가 화면 근처에 보일 때만 SDK를 불러옵니다.
- 썸네일용 좌표는 목록 응답의 **선택 필드** `startLatitude`·`startLongitude`·`endLatitude`·`endLongitude`로 받는 것을 전제로 합니다(백엔드 반영 전). 필드가 없거나 앱 키가 없거나 SDK 로드에 실패하면 기존 대표 관광지 이미지(없으면 공통 배경)를 보여 줍니다.
- 페이지네이션(관광지 목록과 동일하게 첫·마지막 페이지와 현재 페이지 주변 번호만 표시)

### 3.5 관광코스 상세 (`/courses/:id`)

**목적**: 코스를 구성하는 정류지를 순서대로, 각 정류지의 날씨/지수와 함께 보기

**사용 API** (두 API를 나눠 호출한다)

- `GET /api/tour-courses/{id}` → `TourCourseResponse{stops: [spot]}` — DB 조회만이라 빠르다. 코스·정류지 목록과 지도는 이 응답으로 바로 그린다.
- `GET /api/tour-courses/{id}/weather` → `TourCourseWeatherResponse{stops: [{spot, climateIndex, weather}]}` — 기상청 호출이 포함돼 캐시가 비어 있으면 수 초 걸린다. 상세를 기다리지 않고 따로 불러, 도착하면 `stopId`로 매칭해 `weather`·`climateIndex`만 덧붙인다.

**호출 규칙**

- 날씨 요청 타임아웃은 15초(서버의 기상청 타임아웃보다 길게). 실패 시 재시도하지 않고 날씨 영역만 대체 문구를 보여 준다. 코스 정보는 그대로 노출한다.
- 같은 기상청 격자는 서버가 30분간 캐시하므로 날씨 쿼리 `staleTime`은 30분, 주기적 재조회는 하지 않는다.
- `weather`는 정류지별로 null일 수 있고(HTTP 200), `climateIndex`도 저장된 지수가 없으면 null이다. 둘 다 null을 처리한다.

**화면 구성**

- 코스 요약(원본 코스 ID, 정류지 수)
- 세로 타임라인: 정류지 순서 번호(원형 배지) — 관광지명, 실내/실외 배지, 테마 배지, 다음 정류지까지 이동시간, 날씨 카드, 지수 배지
- 날씨가 도착하기 전에는 날씨 카드 자리에 "날씨를 불러오는 중입니다"와 지수 배지 스켈레톤을 보여 준다.
- `weather`가 null인 정류지(또는 날씨 API 전체 실패)는 날씨 카드 자리만 "날씨 정보를 불러오지 못했습니다", 나머지 정보는 그대로 노출(백엔드 부분 실패 허용 설계와 매칭). 날씨 API 전체 실패 시에는 지수 배지를 숨긴다.
- 코스 경로 지도(`CourseMap`): 정류지를 방문 순서 번호 마커로 표시하고 순서대로 경로 선을 잇습니다. 1번 정류지는 더 큰 마커와 "출발" 라벨로 구분합니다. 마커는 버튼이라 키보드로 접근할 수 있고, 누르면 `/spots/:id`로 이동합니다. 앱 키가 없거나 표시할 좌표가 없으면 플레이스홀더, SDK 로드에 실패하면 안내와 "다시 시도" 버튼을 보여 주며, 어느 경우에도 아래 방문 순서 목록은 그대로 표시합니다.

---

### 3.6 추천 코스 (`/recommendations`)

**목적**: 관광기후지수 높은 순으로 "오늘 가기 좋은 코스" 추천

**사용 API**: `GET /api/tour-courses/recommendations?limit=` → `CourseRecommendationResponse[]{courseId, sourceCourseId, climateIndex}`

**화면 구성**

- 추천 API(`limit=20`)를 한 번에 가져와 화면에서 **4개씩** 페이지로 나눠 보여 줍니다(`?page=`, 0부터, 범위를 벗어나면 마지막 페이지). 순위는 페이지를 넘겨도 이어집니다. 한 페이지의 썸네일만 불러오므로 로드뷰가 한 번에 4개를 넘지 않습니다.
- 순위 배지 + 코스 링크 + 지수 배지 리스트(클릭 시 `/courses/:id`)
- 카드 썸네일(`CourseRoadviewThumbnail`): 코스 대표(첫) 관광지 근처 100m 안의 카카오 로드뷰를 상호작용 없이 보여 주고 마커를 표시합니다. 파노라마가 없으면 정적 지도로 대체합니다. 장식 영역(`aria-hidden`)이며 카드가 화면 근처에 보일 때만 불러옵니다.
- 썸네일용 좌표는 추천 응답의 **선택 필드** `representativeLatitude`·`representativeLongitude`로 받는 것을 전제로 합니다(백엔드 반영 전). 필드가 없거나 앱 키가 없거나 SDK 로드에 실패하면 기존 대표 관광지 이미지(없으면 공통 배경)를 보여 줍니다.

**상태**: 결과 0건이면 "관광기후지수 데이터가 아직 수집되지 않았을 수 있습니다"

---

### 3.7 관광기후지수 (`/climate`)

**목적**: 특정 지역의 최신 지수 + 기간별 추이 확인

**사용 API**: `GET /api/regions`, `GET /api/regions/{regionId}/climate-index`, `GET /api/regions/{regionId}/climate-index/range?from=&to=`

**화면 구성**

- 지역 이름 검색 콤보박스(값은 시군구 코드 10자리, 목록 API 실패 시 코드 직접 입력) + 기간(시작일/종료일) + 조회 버튼
- 최신 지수 배지(외부 API 원문 소수 점수 + 등급, 색상은 등급 기준)
- 기간별 추이 꺾은선 그래프(데이터 범위에 맞춘 Y축, 툴팁에 날짜·점수·등급 표시)

**상태**: 지역 지수가 아예 없으면(404) "해당 지역의 관광기후지수가 없습니다", 기간 내 데이터 없으면 "해당 기간에 저장된 지수가 없습니다"

---

### 3.8 관리자 로그인 (`/admin/login`)

**목적**: 관리자 인증, JWT 발급받아 저장

**사용 API**: `POST /api/auth/login {username, password}` → `{token}`

**화면 구성**: 아이디/비밀번호 입력 폼(필수값 검증), 로그인 버튼

**상태**: 잘못된 정보면 서버 에러 메시지 그대로 표시, 성공 시 `/admin`으로 이동

---

### 3.9 관리자 대시보드 (`/admin`)

**목적**: 배치를 기다리지 않고 관광기후지수 수동 동기화

**접근 제어**: 토큰 없으면 `/admin/login`으로 리다이렉트

**사용 API**: `POST /api/admin/climate-index/sync` (Authorization 헤더 필요) → `{requestedRegions, successfulRegions, savedRecords, failedRegions}`

**화면 구성**

- 로그인 계정명 표시 + 로그아웃 버튼
- "지금 동기화" 버튼(진행 중엔 스피너+비활성화)
- 결과 4개 숫자를 카드형 통계로 표시
- 토큰 만료(401) 시 자동 로그아웃 + 토스트 알림

## 6. 디자인 시스템

**컬러**: `primary`(하늘색, 브랜드/버튼) · `success`(녹색, 매우좋음/좋음) · `warning`(노랑/주황, 보통) · `danger`(빨강, 나쁨) · `neutral`(그레이스케일)

**원칙**

- shadcn/ui `Card`/`Badge`/`Button`/`Dialog`/`Skeleton` 기본 사용, 등급→색상은 매핑 함수 하나로 관리
- 로딩은 전부 `Skeleton`, 빈 데이터는 공통 `EmptyState`
- 모바일 우선 반응형(관광지 검색은 특히 모바일 사용성 중요)
